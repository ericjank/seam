# 从反复填表改为 AI 直接协作

## 当前机制与实际问题

Seam 是共享协作状态与任务队列，不是托管业务源码的编程服务。中心保存目标、参与方、消息、产物、提案、凭据授权和验收。各项目 Connector 领取任务，在本地项目目录调用自己的 AI CLI；只有显式发布的结构化消息与动作回传中心。每次 CLI 调用都是新的执行过程，不能假设继承桌面聊天。

实际使用对话暴露了以下断点：

| 断点 | 原因 | 本次处理 |
| --- | --- | --- |
| 人反复复制背景、填写任务和产物 | 消息只保存，不触发 AI；动作提示仅有名称，没有字段规范 | 默认发送即派发；完整动作 JSON Schema，AI 从目标及本地仓库提取资料 |
| 对方没有接手，必须不断点击协商 | 只依赖 AI 手填通知对象，轮次又是整个协作的永久上限 | 批次结束后按实质变化自动交接；每次请求独立有界预算，无进展/失败/人工问题即停 |
| 早期限制、后期授权和既有审批丢失 | 仅传最后 30 条消息，缺提案、凭据状态、验收和真实任务 ID | 单独保留用户指令，补齐结构化状态与 jobId；领取任务时刷新上下文 |
| 后期才发现只能读代码 | online 仅表示连接，Codex 默认只读 | 本地 doctor、显式本地执行策略、界面显示实际适配器/执行模式/测试命令配置状态 |
| 看似完成，动作其实失败 | 先标 completed，再执行动作；失败后无法改回 | 动作与回执事务提交，失败整批回滚并显示原因；领取 CAS 与 attempt 校验防重复执行 |
| 开发被部署前置挡住，界面只显示 500 | 把所有工作串为硬依赖，普通异常隐藏业务原因 | 返回 409 和前置任务名称；AI 应分开并行开发与部署/联合验收任务，保留真实门槛 |
| 补交测试报告使旧确认反复失效 | 所有产物更新都作废全局审批 | 普通证据不重开协商；契约及提案关联产物变化仍触发必要的重新确认 |

## 改进后的使用

1. 每端注册项目和 Agent 一次，在本机私有 env 文件保存中心地址及凭据。
2. 运行 `--doctor` 核对 CLI、执行模式、测试命令。Codex 默认 `read-only`；本机维护者明确允许实施后设置 `SEAM_CODEX_SANDBOX=workspace-write`。平台消息不能提升权限。
3. 创建协作时描述目标。标题可留空，项目只有一个 Agent 时自动绑定。同组织参与项目可下拉选择，不再手抄 UUID；跨组织仍通过对方提供的标识邀请并由对方接受。
4. 在对话中发送一次实施目标。各端 AI 读本地源码与共享状态，创建/更新任务、契约、提案和测试证据。无需人逐项填表。表单仍可用于精确调整。
5. 有实质变化时相关端自动接续；纯状态闲聊、不变产物、需要人类补充、失败或单次预算达到上限时暂停。在执行期间补充的指令会在当前批结束后开启新请求，避免丢失。
6. 只有真正缺失的信息才问人；凭据仍由所有者通过加密授权流程提供。验收必须使用实际测试证据，普通状态更新不能宣告任务通过验收。

“仅留言”不会触发新的执行请求。重复点击推进或运行期间发送消息会合流，领取时刷新最新上下文。每次请求最多 12 批；这里的预算不会成为整个协作的永久锁。

## Connector 配置一次保存

私有 env 文件保留在仓库外，权限设置为 600；不要把真实 Token 提交到 Git。Node.js 要求 22 或以上。

```dotenv
SEAM_PLATFORM_URL=https://seam.example.com
SEAM_AGENT_ID=<注册时生成的 Agent ID>
SEAM_AGENT_TOKEN=<只保存在本机的 Token>
SEAM_PROJECT_ROOT=/path/to/project
SEAM_ADAPTER=codex
SEAM_CODEX_SANDBOX=read-only
SEAM_TEST_COMMAND=pnpm test:contract
```

在 Seam 仓库构建后运行：

```bash
pnpm build
node --env-file=/path/to/private/seam.env apps/connector/dist/cli.js --doctor
node --env-file=/path/to/private/seam.env apps/connector/dist/cli.js
```

本地配置 `workspace-write` 仍保留 Codex 沙箱。无人值守 CLI 不自动批准沙箱外操作；遇到需要额外权限的测试，应报告阻塞并由环境维护者处理。通用 CLI/Claude 的实际权限由本地工具管理，中心显示 external，不推测其具备写权限。`--doctor` 不调用模型或验证中心身份，成功不等于一次真实编码已经通过。

## 验证与边界

单元/服务测试覆盖有界交接、用户输入续接、失败整批回滚、并发领取、租约轮次、任务作用域与依赖。独立 MySQL/HTTP 测试通过真实 Connector 与合成 CLI 验证本地执行和共享交接；不调用真实模型、不读真实业务资料。

```bash
pnpm typecheck
pnpm lint
pnpm test
pnpm build
# 独立、已迁移的测试 MySQL 与运行中的本地服务：
pnpm test:integration
pnpm --filter @seam/platform test:workflow
```

这次改进不等同于历史业务对接已经完成：两端仍需通过各自 Connector 完成业务实现、部署版本核验、本人逐份权限、修订/撤权和异常恢复的真实联合验收。现有实例需升级 Seam 及两端 Connector 后才能使用新链路；旧 Connector 不会自动获得新能力或写权限。

### 本次实际验证（2026-11-11）

- Node 22：全仓 `typecheck`、`lint`、`build` 通过，77 项单元/服务测试通过。
- 独立 MySQL 8.0：既有合成数据增量迁移、空库初始化和重复迁移通过。事件顺序使用数据库自增序列；历史同秒消息已丢失的真实先后无法恢复，按原时间及 ID 确定性回填。升级时先停止旧应用/worker，迁移完成后启动新版。
- 原有三方集成 8 组检查通过，包括一致确认、凭据加密与一次领取、验收、契约变更和组织隔离。
- 新自动协作集成 10 组检查通过，包含双端实际 Connector/子进程执行、上下文复用、运行中续接、事务回滚、旧租约拒绝、普通报告不作废契约、MySQL 并发重复回执仅一次生效。
- 仓库现有浏览器回归 1 项通过；另通过独立临时浏览器验证仅填写目标创建协作、自动绑定 Agent、对话发送即派发和执行记录展示。

以上使用本地测试服务、独立数据库、临时项目和确定性 CLI；没有调用真实模型、修改双方业务项目或升级真实中心。
