# 六项完善与验收

Seam 保存共同目标、协商结果、完整文档、批准和实施证据。项目分析、协商和代码修改由两端本地 Connector 调用各自 Agent 完成。平台不使用中心编程模型替代两端 Agent。每版完整文档经双方确认、管理员批准后才实施；失败后的修复和重新验证保留人工确认，最后由管理员明确决定满意验收或停止。

## 1. 执行中断后的只读核对

Connector 将任务、领取代际、随机恢复密钥及原生会话回合信息持久化。首次心跳绑定密钥摘要。重启通过 `/api/connectors/recover` 核对原任务及密钥，增加领取代际并刷新租约，旧代际不能再提交。密钥不会在任务详情中返回。

Codex App Server 恢复只读读取原回合。已完成回合复用原结果和真实命令证据；实施中断时核对现有代码并保存停止点，在管理员确认原批准范围之前不继续写入。无法确认的状态保留人工关口，不直接重做实施。原会话继续使用，页面执行记录显示原回合编号、只读核对方式和代码指纹。

这不是通用文件回滚：已产生的部分修改会保留。当前目录或批准变化时不能使用旧停止点继续。

## 2. 最终决定及报告封存

协议9的终止请求明确携带 `decision: accepted | stopped` 和当前 `reportHash`。满意验收仅在当前实施及联合验证全部通过、无待审阻塞时可用。报告已变化时返回409，客户端须重新查看当前报告。

最终记录包含决定、管理员、时间、修订、共同文档哈希、审阅报告哈希及封存报告哈希。封存时保留原报告内容并追加决定，不改写历史失败结果。停止未完成任务只表示停止，不表示验收通过。

## 3. 公开证据与截图

Trace 导出识别通用 token、secret、密码、API key、URL 参数、源码和环境赋值及编码变体。公开 Trace 保留脱敏动作、网络和DOM；内嵌二进制截图使用占位图，原件私有保存并记录哈希。

产品截图统一调用 `capturePublicScreenshot`，捕获时遮盖凭据和密码区域，写出 `.public.json` 哈希回执。导出必须核对该回执；缺失或不匹配的图片不得进入公开证据包。`data-sensitive` 或 `data-secret` 可声明额外遮盖区域。不要直接复制原始浏览器目录、Connector 配置、journal 或私有 bootstrap。

## 4. 未变化参与方仅验证

共同契约中的责任可声明 `mode: verify_only`。它仍由双方协商、管理员批准。平台要求该端此前本地实施已通过，当前工作区和测试指纹与原实施一致，并且不是本轮失败接口的服务发布方、没有待修改测试。

满足条件时 Connector 引用原实施证据，明确记录本轮未调用实施模型、未重新执行本地单元测试；随后仍执行本轮真实联合命令及固定HTTP检查。目录漂移或证据不符时转为待管理员处理，不冒充通过。报告分别显示复用的原实施结果和本轮新验证结果。

## 5. 唯一HTTP规范与轻量交接

协议9的 `httpDefinitions` 保存每种HTTP检查的唯一规范，`acceptanceCases[].httpCheckRefs` 使用规范编号和本端检查编号引用。规范存储、Native输出和审批文档保持一致，固定执行器只在验证边界展开。重复、缺失引用或同时使用引用及非空内联检查会被拒绝。

旧接口可接收内联检查并规范化存储；Native9的结构化输出只生成规范及引用。已解决的机器资料通知不再重复灌入后续交接，人工消息继续保留。完整人类审批文档不会因机器交接简化而缩减。

## 6. 定位到字段的失败摘要

固定HTTP检查保留完整请求、响应和命令证据，同时形成结构化根因：需求编号、服务发布项目及Agent、方法和路径、失败字段、期望及实际值。页面和报告可直接定位问题，例如 `subtotal` 期望24000、实际24001。

## 验证边界

自动测试分别标注纯单元、确定性Agent夹具、真实HTTP/MySQL/Connector以及一端真实Codex加虚拟对端。真实模型验收必须从新任务冷启动，冻结平台、Connector和运行器指纹，不以恢复人工接管的旧任务替代。覆盖真实执行写文件后中断、管理员确认续接、修复审批、双方新联合验证和最终满意封存。双真实端验收继续搁置，不能据本轮结果宣称已经完成。
