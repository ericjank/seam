# 协作可靠性与轻量修复（协议 6）

平台承担消息传递、共享事实与文档、审批状态、调度及证据归档。业务分析、实施和修复诊断仍在项目本地 Agent；资料哈希核对和已配置命令的结果汇总由 Connector 确定性处理，无需模型重复转写。平台没有新增中央编程 Agent。

## 升级与兼容

构建并重启两端 Connector（`pnpm --filter @seam/connector... build`），保留原有状态目录、项目、Agent Token 和本机 Codex 配置。心跳报告 `protocolVersion=6` 及资料查询能力。新托管任务会明确列出需要升级的项目和 Agent，能力不足时拒绝创建；旧任务仍可按原协议继续。查询触发新能力时会升级任务协议，避免旧 Connector 将只读查询误当实施。旧客户端的队列选择会跳过不兼容资料任务，继续领取可处理的普通任务。

## 自动查找与事实复用

先读本地和共享资料，仍缺失才向对端询证。每个问题有稳定 key、来源、版本、有效期和独立预算；成功问题不占失败预算。每轮查找有 10 分钟期限，最多三个 attempt，自动重试退避为 2 秒、4 秒。恢复由持久化 outbox、Connector 心跳/轮询及有权限的任务页面读取触发；所有端点和页面均不活跃时不会凭空启动后台计时服务，恢复访问后处理过期任务。

答复绑定 requestId、修订及 attempt，迟到回执不能覆盖新结果。穷尽时管理员可以点击“重新查找”，无需重填目标；管理员补充事实按具体问题保存，不会覆盖同一项目的其他问题。

事实索引跨修订保存 canonical value、来源版本、Connector 实际计算的文件 SHA-256 和 TTL。命中未过期缓存时先由原资料端只读核对当前文件哈希，未变化自动回执，省去模型调用；资料变更或无法核对则重新查找。仅共享文字、没有可核验文件哈希时仍由 Agent 查证。管理员提供的事实明确标记来源和有效期。多方值不一致时显示“冲突”，要求提供方核对版本，未达成一致前不复用。

## 失败分类和人工确认

代码错误 `code` 起草新修复文档，保留原失败证据，双方确认完整新文档后由管理员批准，才重新实施和验证。`environment`、`authorization`、`missing_information`、`unknown` 留在原修订；先处理环境、权限或自动找资料，再由管理员点击“确认处理完成并重试”。找到资料不代表允许重新实施。重试前失败报告进入历史归档，审计记录批准人；只清除受影响方结果，不重复跑已通过方。

普通“未执行”不会自动当作代码错误。固定命令非零但没有实际断言失败证据时归为未知，避免把工具缺失当成业务修复。本机权限不由远程文本提升。测试/代码指纹变化应重新起草文档；不能用环境重试绕过。

## 测试指纹和独立 HTTP 验收

计划由 Connector 采集 Git HEAD、工作区和现存测试资料指纹，完整共同文档展示这些记录。实施后冻结测试文件集合；联合阶段新增、修改、删除测试资料均会停止，要求重审。修复若确需改原测试，必须在 `contract.testChanges` 明确项目、相对路径及理由，进入完整文档审批。

自动发现覆盖常见 test/spec 文件及 tests/specs/fixtures 目录，最多 500 个文件、深度 8 层、单文件 8 MB，跳过依赖、构建和隐藏目录，不等价于所有语言的完整依赖图。超出范围的验收依赖应放入受保护测试目录并明确声明。文件哈希拒绝秘密路径、符号链接和项目外文件。

API 集成契约为每个共享服务声明带业务字段期望的 `acceptanceCases[].httpChecks`。固定 Connector 按已批准请求、状态码和响应字段独立验证，结果绑定文档 hash 与规范 hash；测试脚本同名“通过”不能掩盖实际响应错误。健康探测不能代替业务检查。请求仅允许已发布服务 origin、无凭据和跳转，10 秒超时、64 KiB 正文上限。本地网络权限不足或服务过期为未执行。

这些检查证明声明范围内的响应约束，不等价于所有业务语义或防范已被攻破的本机 Connector。非 HTTP 场景和历史契约如无独立规范，文档明确显示只有命令证据，不伪造独立业务验收。

## 轻量修复与结果回执

修复方优先 `plan.amend` 提交差异；协调方优先 `plan.patch` 仅提交变化字段。平台确定性复用原契约，遗漏字段保持原值，重新生成完整文档、hash 和双方确认，再等待管理员批准。不得删要求、用例、断言或改弱独立 HTTP 期望。

`joint.test.mjs` 等脚本使用 Connector 提供的 `SEAM_SERVICE_URL` 和 `SEAM_REVISION`，无需每版为地址或修订号改测试。平台不能远程替换 `SEAM_TEST_COMMAND`。当本机配置命令与批准用例一致、实际成功断言完整且独立检查通过时，Connector 直接生成真实联合回执，无需调用模型写重复报告。失败仍保留原始记录并走对应分类流程。

原生统计区分消息正文、结构 schema、工具输出、模型运行时计数。资源读取识别绝对及相对路径的显式读取命令，属于尽力识别的命令归因，不声称操作系统级文件审计或精确计费。

管理员最终手动确认终止任务的门控保持不变。第 6 项双真实 Agent 验收暂不执行。

## 协议 7：独立调度、事实关口和验收覆盖

托管任务按参与方去重派发。一个端仍在长任务中时，另一个端的有界重试或只读资料答复可以独立领取；普通协作每端每修订每阶段最多 12 次，资料查找使用原有独立的超时与重试预算。平台不调用中心模型实施业务，本地 Connector 调用本端 Agent；平台负责状态、交接、固定核验、审计和管理员关口。

本方计划通过 `factRefs` 声明使用的共享事实，共同契约必须包含全部计划已引用的事实。每版需重新核验来源，保存的分析先暂存；来源、值未变时直接恢复分析，避免模型重写。来源变化则作废依赖分析和旧文档，重新规划。完整文档保存 key、value 和来源指纹。批准时若已过期，保存原管理员对该 hash 的批准意图，仅安排只读复核；来源未变且批准人仍有权限时自动续接原批准。来源变化或权限撤销不会执行旧文档。未声明的事实依赖无法靠结构校验推断，Agent 仍须准确引用。

每个有效需求声明 `verification=http|command|review`。HTTP 要求必须关联至少一项固定 Connector 独立检查；每个共享 API 至少包含不同请求的成功与错误场景。页面和完整文档显示具体需求、检查及项目。验收的广度仍取决于双方审阅的契约，不能用数量证明业务完全覆盖。

HTTP 连接、读取响应、解析、字段断言、策略上限及权限拒绝分别记录失败阶段。响应中断、超时、读取上限不被当成代码断言失败；未知原因先派发只读诊断。诊断并不授予修改权限，后续实施与验证继续等待管理员确认。真实字段差异、检查标识、实际命令引用优先交接，原始报告完整保存在按需资源中；修复阶段 Native 仅公开增量 amend/patch，最后仍生成并确认完整文档。

阶段变化与状态在同一事务保存为顺序事件，`GET /api/collaborations/:id/events?after=...&limit=...` 可重放短暂阶段。`/executions` 提供有界的任务、阶段和构建指纹查询，不返回原始执行载荷。平台健康接口和 Connector 回执的 `sourceId` 由实际源码清单生成，辅助确认本次执行使用同一构建；它不是远程可信硬件证明。

本地模拟控制器创建自己的子进程并监视退出，异常退出最多自动重启两次；Connectors 与服务保持运行，通过已保存的状态和事件接续同一任务。语义断言失败直接失败，不作为崩溃重试。测试可设置 `SEAM_SIMULATION_INJECT_CONTROLLER_EXIT=after_first_approval` 注入一次控制器退出；不需要 PID 接管。故障重启回归：`pnpm test:simulation:controller`。完整修复及信息查找场景：`SEAM_SIMULATION_SCENARIO=repair-information pnpm test:simulation`。
