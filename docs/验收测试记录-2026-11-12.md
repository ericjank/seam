## 发现并处理的问题

### 时间显示与首次渲染不一致

Docker UTC和浏览器北京时间的默认日期格式导致React418。改为统一Asia/Shanghai格式并复用日期helper，覆盖跨时区单测；最终浏览器无pageerror。真实主模型任务完成后对日期显示进行了修复并重建镜像，随后完成HTTP/浏览器回归；没有把它写成重新执行了一遍主模型场景。

### 折扣null边界漏测

整理报告时发现历史虚拟提供方使用 `discountPercent ?? 0`，显式null会得到200，违反双方方案中非法折扣应400的要求。历史第二轮10次HTTP只覆盖缺省零折扣、显式10/100和部分错误输入；显式0由原提供方Node测试覆盖。

修复生成器，仅在undefined时使用默认0；生成的Node测试增加null、布尔等类型。完整运行器现在也验证显式0和非法折扣的消费方调用及提供方直接HTTP响应，记录新运行的实际请求数，不再固定沿用历史10次。

补充脚本通过历史真实客户端实际HTTP复现旧null→200，再在全新虚拟提供方验证11条用例：缺省/0/10/100返回200，null/false/true/字符串/小数/-1/101返回400。生成提供方测试3项通过。脚本12条断言包括1条已知缺陷复现与11条新实现通过，不能说历史实现已全部合格。历史源文件SHA256前后一致，原6/10结果与已终止任务不变，未调用模型，也不是第三轮真实Codex全流程。

可复现补测：

```bash
node scripts/simulation/discount-boundary-check.mjs \
  --historical-provider /path/to/seam-full-simulation-RUN/provider/service.mjs \
  --consumer /path/to/seam-full-simulation-RUN/consumer/client.mjs \
  --evidence-dir /path/to/separate-evidence
```

脚本只接受已存在的隔离模拟目录，历史文件只读，不访问中心或模型。完整场景复现与浏览器启动规则见[端到端模拟验证](端到端模拟验证.md)。
